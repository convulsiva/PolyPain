# Правила создания веток

# Главные ветки

- **`master`** - стабильная версия
- **`develop`** - основная ветка разработки (сливаем туда все изменения)

# Общая структура веток

### Общий вид ветки

```
<type>/<scope>/<short-description>
```

## Типы веток

- **`feature/`** – новые фичи.
- **`bugfix/`** – исправление багов.
- **`hotfix/`** – срочные фиксы (например, критические баги в проде).
- **`refactor/`** – рефакторинг (улучшения существующего кода, без изменения его функциональности).
- **`docs/`** – работа с документацией.
- **`chore/`** – вспомогательные задачи (настройка CI/CD, конфиги).
- **`sandbox/`** – тестовый код, который не будет сливаться с develop.

## Области

- **`backend/`**
- **`frontend/`**
- **`bot/`**
- **`infra/`** – если потребуется настройка инфраструктуры (деплой, CI/CD).
- **`common/`** - остальное.

## Примеры

- `feature/backend/booking-api` – создание API бронирования.
- `feature/frontend/booking-page` – страница бронирования.
- `feature/bot/admin-notifications` – уведомления для админа в боте.
- `bugfix/frontend/mobile-layout` – исправление верстки на мобилках.
- `refactor/backend/models` – рефакторинг моделей.
- `docs/backend/api-docs` – обновление документации API.

# Правила

1. Одна ветка — одна **конкретная** задача (новая фича, багфикс, рефакторинг). Одна ветка должна жить **1-3 дня**, максимум неделю. %% Дада, неделя максимум.... :) %%

2. Делаем **небольшие** ветки, которые можно быстро ревьюить и мёржить.

3. **Не работаем в** `main` и `develop` **напрямую** – только через PR.
